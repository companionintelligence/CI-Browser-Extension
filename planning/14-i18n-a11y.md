# 14 — Internationalization & Accessibility

## Problem

### i18n
- Every user-visible string in the codebase is inline English. Examples: status messages in [background.ts:705](../src/entrypoints/background.ts) ("Authentication expired. Please log in again."), button labels in [popup/App.tsx](../src/entrypoints/popup/App.tsx), tooltip copy, blacklist manager text.
- `wxt.config.ts` declares no `default_locale`, no `_locales/` directory exists, and no translation pipeline is configured.
- The CI ecosystem is positioned as a personal/private product; non-English speakers are second-class users with no path to localization.

### a11y
- Popup was recently rewritten with shadcn/ui ([packages/shadcn/](../packages/shadcn/)) which has reasonable a11y defaults, but no audit has been done.
- Keyboard navigation through the popup has not been verified.
- Screen-reader labels on icon-only buttons are not consistent.
- Color contrast in dark mode (added in PR #34, since closed/reopened context) has not been measured against WCAG AA.
- Status messages update via plain DOM updates — no `aria-live` region for sync progress announcements.
- Focus management on modal-like flows (blacklist manager open/close) untested.

## Goals

- All user-visible strings sourced from `_locales/`, with English the canonical baseline.
- Pipeline for adding new locales without code changes.
- Popup passes WCAG 2.1 AA across keyboard, screen reader, contrast.
- Automated lint catches new untranslated strings and missing a11y attributes.

## i18n approach

### 1. Switch to `browser.i18n.getMessage`

WebExtension's built-in i18n is the path of least resistance:

```
_locales/
  en/messages.json
  es/messages.json
  de/messages.json
  ja/messages.json
```

```json
{
  "popup_sync_button":     { "message": "Sync now", "description": "Button to trigger manual sync" },
  "auth_expired":          { "message": "Authentication expired. Please log in again." },
  "blacklist_add_domain":  { "message": "Add domain to ignored list" }
}
```

Usage:

```ts
const t = (key: string) => browser.i18n.getMessage(key);
<Button>{t("popup_sync_button")}</Button>
```

In `wxt.config.ts`:

```ts
manifest: {
  default_locale: "en",
  name: "__MSG_extension_name__",
  description: "__MSG_extension_description__",
}
```

### 2. Extraction tooling

Custom ESLint rule `no-untranslated-jsx` rejects any string literal as a JSX child that isn't wrapped in `t()`. Limits accidental regressions.

A script `npm run i18n:extract` walks the codebase, collects all `t("…")` keys, and diffs them against `_locales/en/messages.json`:
- New key → added with a TODO description.
- Removed key → flagged for cleanup.

### 3. Pluralization + interpolation

`browser.i18n.getMessage` supports placeholders but not pluralization. For plural-heavy strings (`{count} visits synced`) wrap with a thin helper:

```ts
function tPlural(key: string, n: number) {
  return n === 1 ? t(`${key}_one`) : t(`${key}_other`).replace("{count}", n.toString());
}
```

For more complex needs, integrate [Format.JS](https://formatjs.io/) — but only if pluralization becomes painful.

### 4. RTL support

CSS uses logical properties (`margin-inline-start`, `padding-inline-end`) instead of `margin-left` / `padding-right` wherever possible. Tailwind v4 supports these. Add an audit pass.

`html dir` set from locale at popup mount.

### 5. Locale precedence

Order: explicit user preference (settings dropdown) → `browser.i18n.getUILanguage()` → English fallback.

### 6. Initial locale set

Ship `en` first. Then add `es`, `de`, `ja`, `fr`, `pt-BR` as bandwidth allows. Use a community translation platform (Crowdin, Weblate) once we have ≥3 locales.

## a11y approach

### 1. Audit baseline

Run [axe DevTools](https://www.deque.com/axe/) against the popup in Chrome. Capture findings as a checklist; ticket the violations.

Likely findings:
- Icon buttons without `aria-label`.
- Form inputs without programmatic labels (shadcn's `<Field>` usually adds them; verify).
- Color contrast in dark mode.
- Focus indicators clobbered by Tailwind `focus:ring` defaults.

### 2. Keyboard nav

- Every interactive control reachable via Tab.
- Tab order matches visual order.
- Escape closes modals; Enter activates primary action.
- Custom test in Playwright that opens the popup and tabs through every focusable, asserting on the focused-element trail.

### 3. Screen reader

- All icon-only buttons get `aria-label`.
- Sync status surfaces in an `aria-live="polite"` region:

```tsx
<div aria-live="polite" aria-atomic="true" className="sr-only">
  {historySyncStatus}
</div>
```

- Toggle switches use `<input type=checkbox role=switch aria-checked={...}>`.
- Test with VoiceOver (macOS) and NVDA (Windows). At least one of each on the next two releases.

### 4. Color contrast

- Run `axe-core` color-contrast rule on dark and light themes.
- Adjust Tailwind palette where contrast < 4.5:1 for normal text or < 3:1 for large text.

### 5. Motion & reduced motion

Honor `prefers-reduced-motion`:

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

### 6. Focus management

- On blacklist modal open, move focus to first input.
- On close, return focus to the trigger button.
- Use a `<dialog>` element or a small focus-trap helper.

### 7. Automated checks

Add `axe-playwright` to E2E tests ([05 — testing](05-testing.md)). Failing axe violations fail the build for `serious` and `critical` levels.

```ts
test("popup has no a11y violations", async ({ page }) => {
  await page.goto(`chrome-extension://${ext}/popup.html`);
  await injectAxe(page);
  await checkA11y(page, undefined, { detailedReport: false, axeOptions: { rules: { /* ... */ } } });
});
```

## Migration / sequencing

i18n and a11y can land independently but benefit from being done in the same pass per file (touch the JSX once, fix both).

1. Set up `_locales/en/messages.json` and the `t()` helper.
2. Sweep popup files one component at a time, extracting strings and fixing a11y as you go.
3. Add the ESLint rule once popup is fully migrated.
4. Add axe-playwright check to CI.
5. Recruit translators for `es` / `de` / `ja` (likely community contributors).

## Risks & open questions

- **String review fatigue** — designers/PMs need to review wording in `messages.json`. Build a simple review tool or use Crowdin from the start.
- **Pluralization without a library** — `browser.i18n.getMessage` doesn't do CLDR plurals. Most strings won't need it; intricate ones get Format.JS.
- **shadcn customization** — some shadcn primitives have their own ARIA. Don't override unless improving.
- **Mobile a11y** — Safari iOS and Firefox Android have different screen-reader behaviors (VoiceOver vs. TalkBack). Test both.
- **Translation drift** — features ship faster than translation. Decide: do we hold features until all locales are translated, or ship English and back-fill? Recommended: ship English, mark missing keys as fallback-to-EN at runtime.

## Acceptance criteria

### i18n
- [ ] No literal English JSX children remain in `src/entrypoints/popup/**` (ESLint enforced).
- [ ] `_locales/en/messages.json` exists with ≥80 entries covering popup, blacklist manager, setup wizard.
- [ ] At least one additional locale (Spanish recommended) ships in v1.5.
- [ ] Popup language matches browser locale by default and can be overridden in settings.

### a11y
- [ ] Axe Playwright audit shows 0 `serious` or `critical` violations on popup.
- [ ] Every icon-only button has an `aria-label`.
- [ ] Sync status announced to screen readers via `aria-live`.
- [ ] Keyboard-only navigation through popup verified manually and via Playwright trail test.
- [ ] Color contrast measured ≥ 4.5:1 (normal) / ≥ 3:1 (large) for both themes.
- [ ] `prefers-reduced-motion` honored.
